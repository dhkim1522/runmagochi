## 기준

- **한눈에**: 러닝 중 화면을 팔을 흔들며 햇빛 아래에서 1초 본다고 가정. 거리 숫자 크기·대비, 둘째 정보(목표·페이스)가 따라오는지.
- **위계**: 화면마다 주요 행동 하나(`시작`·`일시정지`·`확인`)가 바로 보이는지, 요약에서 성장 → 기록 순서가 읽히는지.
- **일관성**: 세 화면이 같은 재료·같은 선택 표시·같은 아이콘 결인지.
- **접근성**: 위 측정 + 버튼 경계, 포커스 표시.
- **AI 티**: 이름을 가리고 다른 앱에 갖다 놓아도 성립하는지(성립하면 낮음).
- **펫 통합**: 도트 친구가 화면과 같은 재료인지, 상자 안에 붙인 스티커인지.

## a · 스킬 (ui-ux-pro-max, 23점)

| 기준 | 점수 | 한 줄 이유 |
| --- | :-: | --- |
| 한눈에 | 4 | Jua 120 진갈색 거리, `km` 아래 줄, 목표 막대가 바로 아래. 다만 아래 무대가 커서 페이스(26)가 화면 가운데에 묻힌다 |
| 위계 | 4 | "누르는 것만 도톰" 규칙이 세 화면 모두에서 지켜져 누를 곳이 한눈에 보인다. 요약의 `코인 +200` 굵은 파랑이 보상을 살린다 |
| 일관성 | 5 | 같은 클레이 재료, 별 코인 아이콘, 둥근 선 아이콘(달리는 사람·발바닥·가게)이 세 화면을 꿴다 |
| 접근성 | 4 | 측정 모두 통과. 주황 버튼 면은 2.6:1 이지만 진한 립이 경계를 만든다 |
| AI 티 | 3 | 승인된 클레이라 이 앱 것이지만, "귀여운 둥근 앱" 문법 안에 있다 |
| 펫 통합 | 3 | 무대가 둥근 상자라 병아리가 상자 속 스티커처럼 보인다. 러닝 중 무대는 빈 상자 비율이 크다 |

- 잘한 것: 홈 무대 안에 코인·톱니·이름·레벨 막대를 모아 "내 친구 칸" 이 하나로 읽힌다. 요약은 레벨 업 무대 안에 보상 행 3개를 넣어 성장이 먼저, 기록이 다음으로 자연스럽게 흐른다. 경로·구간이 평평한 판이라 소음이 지금 앱보다 확실히 줄었다.
- 출시 전 고칠 것
  - [P1] 러닝 중 무대 높이를 줄이고(5배 → 4배, 또는 무대 높이 220) 페이스 판을 위로 붙인다. 지금은 거리–페이스–버튼 사이 빈칸이 커서 시선이 세 번 끊긴다.
  - [P2] 요약 구간 막대 색이 주황이라 `확인` 버튼과 같은 무게로 읽힌다. 막대는 `accent` 나 `primary` 옅은 단계로 낮춘다.
  - [P2] 경로 시작점(파랑)·끝점(진갈) 점이 겹쳐 있어 어느 쪽이 시작인지 모른다. 시작점 테두리를 키우거나 끝점에 깃발 모양을 준다.
  - [P3] 홈 `거리`/`시간` 분할 버튼이 칩과 같은 굵기의 립을 가져 "칩 위의 칩" 이 된다. 분할은 립 없이 선택 칸만 도톰하게.

- 잘한 것: 친근하고 가볍다. 요약 보상 3행을 흰 카드 하나에 줄 간격만으로 묶어 지금 앱보다 훨씬 조용하다. 경로·구간을 초록 한 색으로 맞춰 정보 판이 차분하다.
- 출시 전 고칠 것
  - [P1] 연두 버튼에 진한 립이나 1.5px 진초록 테두리를 더해 면 경계를 3:1 이상으로.

  - [P2] 분할 선택 표시를 칩과 같은 규칙으로 맞춘다.

## 같은 방향, 다른 트랙: 도구가 바꾼 것

| 방향 | 스킬 트랙이 더 나은 점 | 캔버스 트랙이 더 나은 점 |
| --- | --- | --- |
| a | 아이콘을 방향에 맞게 직접 골라 그렸다(별 코인·발바닥). 보상 위계(`코인 +200`)가 살아 있다 | 홈이 844 안에 꽉 맞고, `km` 를 거리 옆에 붙여 한 줄로 읽힌다 |
| b | 요약 보조 버튼 크기·보상 강조가 맞다 | 세로 리듬이 촘촘하고 여백 버그가 없다. 홈 목표 판 묶음, 요약 지표 3칸, 도트 경로가 더 정교하다 |
| c | 선택 표시가 비교적 일관되고 코인 아이콘이 맞다 | 홈 높이 배분, 말풍선 꼬리, 마스코트 무게감 |

두 트랙에서 반복된 차이:

- **캔버스는 화면을 한 장의 고정 아트보드(390×844)로 짜서 세로 배분이 더 정확하다.** 홈·러닝 중에서 빈 띠가 덜 생겼다(a 러닝 중만 예외). 스킬 트랙은 한 HTML 에 세 화면을 넣고 `min-height` 로 늘려 빈 띠가 생겼다(b 홈·러닝 중).
- **캔버스는 부품을 기본값으로 채우는 경향이 있다.** 일반 선 아이콘 세트(a·c), `$` 코인(c), 세 방향 모두에 같은 `새 외형 단계!` 알약 배지, 보상 값(`코인 +200`)을 작은 회색으로 내림 — 방향이 달라도 같은 습관이 나왔다. 스킬 트랙은 방향 문서와 스킬 검사(Impeccable 검출기, taste-skill inspect)를 돌며 이런 부분을 직접 그렸다.
- **캔버스는 결과를 캔버스 안에서 바로 렌더해 보지 못해** 요약 높이·버튼 크기 같은 수치 확인이 한 번뿐이었다(트랙 2 보고). 스킬 트랙은 검출기·측정 스크립트를 반복해 검출기 0건으로 끝났다. 반면 스킬 b 의 제목 여백 버그처럼 "검사를 고치다 생긴" 회귀가 하나 있다.
- **방향 문서가 강할수록 트랙 차이가 작다.** b 는 모티프 규칙이 촘촘해 두 트랙이 거의 같은 화면을 냈고, a·c 는 문서가 느슨한 부분(아이콘·보상 강조)에서 갈렸다.
- 스크린샷 배율이 다르다(스킬 2배 780px, 캔버스 1배 390px). 비교 페이지에서 캔버스 쪽이 덜 선명한 것은 캡처 배율 때문이지 디자인 차이가 아니다.

## 추천

**`b · 캔버스` 를 바탕으로 하고, `b · 스킬` 에서 요약의 보조 버튼 크기(17)와 `코인 +200` 강조를 가져온다.** 짧게 답하면 "b · 캔버스".

1. **러닝 앱의 1순위 기준(한눈에)에서 b 가 가장 강하다.** 거리 140 검정이 17:1, 왼쪽 정렬로 화면 폭을 채워 "거리를 화면 1/3 크기로"(screens.md) 원칙에 가장 가깝다. 코발트 블록 위 흰 버튼은 햇빛 아래에서도 경계가 7:1 이상이다. c 의 연두 면(1.2:1)과 a 의 주황 면(2.6:1)은 야외에서 약하다.
2. **펫 통합이 다른 두 방향과 질적으로 다르다.** a·c 는 캐릭터를 상자나 원 안에 "올려놓았고", b 는 캐릭터의 픽셀 한 칸이 화면 전체의 재료다. 병아리가 언덕을 밟고 트랙을 달리며, 노랑이 화면의 유일한 따뜻한 색이라 시선이 늘 친구에게 간다. 앱의 핵심 루프(달리기 → 성장)가 화면 모양으로 보인다.
3. **AI 티가 가장 적다.** c 는 요즘 한국 핀테크 앱과 구별되지 않고, a 는 승인된 정체성이지만 "귀여운 앱" 범위다. b 는 이 앱 이름을 지우면 성립하지 않는다 — 포트폴리오로도 가장 설명하기 쉽다.
4. **캔버스 쪽이 출시에 가깝다.** 같은 모티프에서 세로 리듬이 촘촘하고 버그가 없다. 남은 고칠 것 두 개(보조 버튼 크기·보상 강조)는 스킬 b 에 이미 답이 있다.

고를 때 감수할 것:

- **승인된 말랑 클레이(페이즈 2.5)를 버리는 결정**이다. 새 결정 기록, `docs/design/tokens.json`·`theme.dart` 토큰 교체, 디자인 시스템 문서 갱신이 따른다. 글꼴도 Jua·Noto Sans KR → Jost·Gothic A1 로 바뀌어 작업 17(글꼴 서브셋)의 대상이 달라진다.
- **다크 모드가 아직 없다.** 코발트 블록이 다크에서 어떻게 보일지(블록을 코발트 그대로 두고 바탕만 어둡게 할지) 작업 10 에서 정해야 한다. 젤리·도토리처럼 노랑이 아닌 캐릭터가 코발트 위에서 잘 보이는지도 그때 확인한다.
- 회색 바탕이 차갑게 느껴질 수 있다. 입문 러너의 첫인상을 베타에서 묻는다.

정체성을 지키는 쪽을 원하면 **`a · 스킬`** 이 차선이다. 6안 중 일관성이 가장 높고 지금 토큰을 그대로 쓰므로 옮기는 비용이 거의 없다. 다만 a 를 고르면 러닝 중 무대 축소와 구간 막대 색 조정은 꼭 해야 하고, 캐릭터가 "상자 속 스티커" 인 한계는 남는다. c 는 두 트랙 모두 추천하지 않는다 — 무드보드의 가벼움은 얻지만 야외 가독성과 고유성을 함께 잃는다.
