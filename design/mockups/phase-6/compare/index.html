런마고치 UI 후보 비교

세 방향(a 말랑 클레이 · b 도트 한 칸 · c 연두 무드보드)을 두 트랙(디자인 스킬로 짠 HTML, Claude Design 캔버스)으로 그린 6안입니다. 홈 · 러닝 중 · 요약 세 화면을 같은 문구와 같은 러닝 기록으로 그렸고, 같은 기준으로 점수를 매겼습니다. 화면을 누르면 크게 볼 수 있어요.

추천

b · 캔버스

요약 화면의 보조 버튼 크기와 코인 +200 강조는 b · 스킬에서 가져옵니다.

  1. 야외에서 가장 잘 읽혀요. 러닝 중 거리 140px 검정이 바탕 대비 17:1이고, 왼쪽 정렬로 화면 폭을 채웁니다. 코발트 위 흰 버튼은 햇빛 아래에서도 경계가 분명해요.
  2. 캐릭터와 화면이 같은 재료예요. 도트 한 칸과 계단 모서리가 버튼, 막대, 경로, 아이콘이 되고 병아리는 코발트 언덕을 밟고 섭니다. 노란 병아리가 화면의 유일한 따뜻한 색이에요.
  3. 이 앱만의 모양이에요. 이름을 가리면 다른 앱에서는 성립하지 않습니다.
  4. 캔버스 쪽이 출시에 더 가까워요. 세로 배분이 촘촘하고, 스킬 쪽 러닝 중 제목 여백 버그가 없습니다.

감수할 것: 승인된 말랑 클레이를 바꾸는 결정이라 토큰·글꼴 교체와 새 결정 기록이 따르고, 다크 모드는 아직 없습니다. 지금 정체성을 지키려면 차선은 a · 스킬(23점)입니다.

18장 모두 390px에서 가로 넘침이 없고, 글자 대비 4.5:1(24px 이상 3:1)과 글자 13px 이상을 지킵니다. a · 캔버스와 c · 캔버스의 거리/시간 분할 버튼만 높이 44px(트랙 여백을 더해 48px)입니다. 6안 모두 라이트 모드만 있어요.

방향 a

말랑 클레이 다듬기

지금 앱의 승인된 클레이를 출시 품질로 다듬습니다. 테두리와 립은 누를 수 있는 것과 캐릭터 무대에만 남기고, 읽기만 하는 정보는 평평한 판으로 낮췄어요.

a에서 도구가 바꾼 것

스킬은 아이콘을 방향에 맞게 직접 골랐고 보상 강조가 살아 있습니다. 캔버스는 홈 높이 배분이 더 정확하지만 아이콘과 보상 표시를 기본값으로 채웠어요. a 안에서는 스킬이 낫습니다.

모티프 규칙이 촘촘해 두 트랙이 거의 같은 화면을 냈습니다. 캔버스는 고정 아트보드라 세로 배분이 정확하고, 스킬은 요약의 보조 버튼과 보상 강조가 맞아요. 둘을 합치면 남는 문제가 거의 없습니다.

c에서 도구가 바꾼 것

캔버스는 마스코트의 무게감과 홈 배분이 낫고, 스킬은 선택 표시와 아이콘이 맞습니다. 점수는 같아요. 어느 쪽이든 야외 가독성과 고유성이 a·b보다 약해 추천하지 않습니다.

두 트랙에서 반복된 차이

  • 캔버스는 화면을 390×844 아트보드 한 장으로 짜서 세로 배분이 더 정확해요. 스킬은 한 HTML에 세 화면을 넣어 빈 띠가 생기곤 했어요.
  • 캔버스는 부품을 기본값으로 채우는 습관이 있어요. 일반 선 아이콘, $ 코인, 세 방향 모두 같은 알약 배지, 작게 내려간 코인 +200.
  • 스킬 트랙은 검출기와 측정을 반복해 검출기 0건으로 끝났지만, 고치다 생긴 회귀(b 제목 여백)가 하나 있어요.
  • 방향 문서가 촘촘할수록(b) 두 트랙이 비슷하고, 느슨한 부분(아이콘, 보상 강조)에서 갈렸어요.

보는 법

  • 스킬 쪽은 2배(780px), 캔버스 쪽은 1배(390px)로 캡처해서 캔버스 쪽이 조금 덜 선명해요. 디자인 차이가 아닙니다.
  • 요약 화면은 길어서 폰 틀 안에서 스크롤되고, 누르면 크게 볼 수 있어요.
  • 러닝 중 병아리는 실제로는 10fps로 달려요. 캡처는 첫 프레임입니다.

고른 안

점수 추천은 b · 캔버스였지만, 마스코트가 화면의 주인공이 되는 c · 캔버스(연두 무드보드)를 골랐어요. 고르기 전에 c 의 연두 원을 사각 무대(하늘 + 땅 띠)로 바꿔 무대 뒤에 배경 아이템을 깔 수 있게 했고, 지금 앱은 이 방향으로 만들었어요.

근거와 함께 고친 점은 결정 0029에 있어요.
