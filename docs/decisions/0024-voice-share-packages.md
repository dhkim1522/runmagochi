# 0024 음성 안내는 flutter_tts, 공유는 share_plus 를 쓴다

- 상태: 채택
- 날짜: 2026-10-21

## 배경

- 페이즈 5 에서 러닝 중 음성 안내(한국어)와 러닝 요약 공유 카드(이미지 공유)를 넣는다.
- 두 기능 모두 안드로이드·iOS 시스템 기능을 불러야 한다. 이 앱이 쓰는 패키지는 현재 위치·알림·권한·파일 선택 등 기능별 최소 구성이다.
- 이번 페이즈에서 새로 넣는 패키지는 이 둘뿐이다. 그래프는 패키지 없이 직접 그린다.

## 결정

### 음성 안내: flutter_tts

- 기기에 깔린 음성 합성(TTS) 엔진을 부르는 패키지다. 한국어(`ko-KR`) 지정, 읽는 중 다른 앱 소리 줄이기(덕킹)를 지원한다.
- 안드로이드는 오디오 속성을 내비게이션 안내로 두고 읽을 때 일시적 오디오 포커스를 요청한다. 음악 앱 소리는 줄었다가 다 읽으면 돌아온다.
- iOS 는 오디오 범주를 재생으로 두고 `duckOthers` 를 준다.
- 안드로이드 11 이상은 TTS 서비스를 찾으려면 `AndroidManifest.xml` 의 `<queries>` 에 `android.intent.action.TTS_SERVICE` 가 필요해 추가했다.
- 라이선스는 MIT 다.
- `Speaker` 인터페이스 뒤에 두어 화면·기록 코드가 패키지를 직접 모른다. 테스트는 가짜 `Speaker` 로 한다.

### 공유: share_plus

- 시스템 공유 창을 열어 이미지 파일을 카카오톡·인스타그램 등으로 보낸다. 안드로이드와 iOS 를 모두 지원한다.
- 라이선스는 BSD-3-Clause 다.
- Flutter Community 조직이 관리하는 사실상 표준 패키지다.
- `Sharer` 인터페이스 뒤에 두어 화면 코드가 패키지를 직접 모른다. 테스트는 가짜 `Sharer` 로 한다.
- 공유 이미지를 임시 폴더에 쓰려고 `path_provider` 를 직접 의존성으로 올렸다. 이미 다른 패키지(drift_flutter 등)가 끌어오던 것이라 새로 늘어나는 네이티브 코드는 없다.

### 대안

- 직접 플랫폼 채널 작성: 안드로이드·iOS 네이티브 코드를 직접 만들고 유지해야 한다. 이 앱 규모에서는 비용이 크다.
- 미리 녹음한 음성 파일: 숫자(거리·시간·페이스)가 매번 달라 모든 조합을 녹음할 수 없다.
- 공유 없이 이미지 저장만: 사용자가 갤러리에서 다시 골라 올려야 한다.

## 결과

- 음성은 기기에 한국어 음성이 없거나 TTS 엔진이 없으면 나오지 않는다. 초기화·읽기 실패는 로그만 남기고 러닝 기록은 계속한다.
- 음성 안내는 설정에서 끈다(기본 켜짐).
- 네이티브 의존성이 둘 늘어 앱 크기와 빌드 시간이 약간 늘어난다.
- 패키지를 올릴 때 안드로이드 `minSdk`·Gradle 호환을 확인한다.
