# 0022 디자인 다음에 산출물 정리 페이즈를 둔다

- 상태: 채택 (결정 0017 의 페이즈 번호를 한 칸씩 미룸. 페이즈 7·8 순서는 결정 0026 이 바꿈: 실기기 확인 7, 산출물 정리 8)
- 날짜: 2026-10-21

## 배경

- 이 프로젝트를 포트폴리오로 쓸 수 있을 만큼 개발 산출물을 갖추고 싶다.
- 요구사항·시나리오·화면설계·아키텍처 문서는 이미 있지만 개발하며 고쳐 온 것이라, 완성된 앱 기준으로 한 번 정리해야 한다. ERD·시퀀스 다이어그램은 없다.
- 디자인(페이즈 6)이 끝나야 화면 문서를 한 번만 쓸 수 있다.
- 이번 경험으로 다음 프로젝트에서는 필요한 산출물을 먼저 만들고 진행하는 순서를 쓰고 싶다.

## 결정

- 페이즈 6 디자인 완성 다음에 **페이즈 7 산출물 정리**를 둔다.
  - PRD, 유저 시나리오, 화면설계서·와이어프레임, UI 시안·디자인 시스템, 시스템 아키텍처, ERD, 시퀀스 다이어그램
  - 결정 기록 모음, 페이즈별 개발 기록, README 소개
  - 다음 프로젝트용 플레이북 `docs/playbook.md` 와 같은 내용의 스킬
- AI 가 코드를 원본으로 읽는 개발 방식이라 필요 없는 문서는 만들지 않는다: API 명세(서버 없음), 테스트 케이스 문서(테스트 코드가 원본), 일정표(WBS).
- iOS 확장·실기기 확인은 **페이즈 8**, 동시 출시는 **페이즈 9** 가 된다.
- 다른 결정·계획이 "페이즈 7" 로 적은 iOS 확장·실기기 확인은 페이즈 8 에서, "페이즈 8" 로 적은 출시 일은 페이즈 9 에서 한다.

## 결과

- 출시가 한 페이즈 늦어진다.
- 산출물이 완성된 앱과 맞는 상태로 한 번에 정리되고, 다음 프로젝트의 페이즈 구성에 쓸 근거가 남는다.
