# 0032 로그인·서버를 확장 백로그에 올린다

- 상태: 채택
- 날짜: 2026-10-22

## 배경

- 결정 0001 로 서버 없이 기기에만 저장하고, 로그인도 두지 않았다. 서버 이전 순서는 `docs/architecture.md` "서버 이전 경로" 에 있다.
- 로드맵에는 서버 도입이 "사용자가 늘어날 때" 로만 적혀 있고 작업 목록에는 없었다.
- 페이즈 9 출시 범위에 App Store 결제(꾸미기 팩·후원)가 있는데, 결정 0001 은 유료 아이템 전에 서버 검증이 반드시 필요하다고 한다.
- 사용자가 로그인(인증)·데이터베이스·서버 구성을 확장 작업 목록에 미리 넣어 두자고 했다(2026-10-22).

## 결정

- 요구사항 F22 "계정·서버" 를 백로그로 추가한다. 첫 출시(MVP)에는 넣지 않는다. 결정 0001 은 그대로 유지한다.
- 범위(서버 이전 경로 순서)
  1. 로그인(인증)을 추가하고 기존 로컬 데이터를 계정에 연결한다.
  2. 서버 데이터베이스와 API 를 구성하고, 저장소 인터페이스에 서버 구현을 더한다. 로컬 DB 는 오프라인 캐시로 쓴다. 기기 간 동기화가 따라온다.
  3. 보상(경험치·코인) 계산을 서버로 옮겨 조작을 막는다.
- 착수 시점: 유료 아이템을 팔기로 할 때, 소셜 기능(친구·리더보드·챌린지)을 넣기로 할 때, 또는 사용자가 늘어 기기 간 동기화가 필요할 때 중 먼저 오는 때.
- 인증 방식·서버 기술(관리형 백엔드 또는 직접 구성)·비용은 착수할 때 조사해 새 결정으로 정한다.
- 페이즈 9 결제는 후원처럼 게임 보상과 무관한 것만 로컬로 할 수 있다. 유료 꾸미기 팩을 팔려면 F22 의 1~3 이 먼저다. 페이즈 9 계획 때 정한다.

## 결과

- 로드맵 "확장 백로그" 에 F22 가 들어가 잊히지 않는다.
- 지금 코드는 바뀌지 않는다. 저장소 인터페이스·UUID·생성·수정 시각·코인 원장 구조가 이미 서버 이전을 대비한다.
- 계정을 두면 스토어 정책상 앱 안 계정 삭제, 개인정보 처리방침 갱신이 함께 필요하다.
