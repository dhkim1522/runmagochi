# 0028 디자인 에셋은 코드 도트와 도구 스크립트로 만든다

- 상태: 채택
- 날짜: 2026-10-22

## 배경

- 페이즈 6 디자인 완성에서 캐릭터 3종·아이템·배지를 출시 품질로 다시 그리고, 앱 아이콘·스플래시·글꼴을 정리해야 한다.
- 지금 캐릭터는 `tool/sprites/` 의 코드 픽셀 격자(한 글자 = 한 픽셀)로 그린 임시 그림이다(작업 9).
- 그리는 수단 후보는 넷이었다.
  - Aseprite(약 $20): 손으로 그리는 도트 편집기. 결과 파일을 코드 규격(레이어·기준점)에 맞춰 옮기는 일이 따로 든다.
  - 픽셀 생성 AI(PixelLab, 월 약 $12): 빠르지만 프레임·기준점·단계별 얼굴 위치를 맞추기 어렵다.
  - 이미지 생성 모델: 32×32 격자·팔레트가 깨져 다시 찍어야 한다.
  - 코드 도트: 지금 방식. 테스트로 프레임 형식·발끝·face 위치를 검사할 수 있다.

## 결정

- **캐릭터 수단**: 코드 도트로 그린다(2026-10-22 사용자 선택). Aseprite·픽셀 생성 AI·이미지 생성 모델·외주는 쓰지 않는다. pixel-plugin 도 끈 채로 둔다.
  - 그림체는 후보 3개(`design/candidates/character/`, `tool/sprites/candidates/`, 작업 18 에서 지워 git 기록에만 남음)를 주변에 보여 투표로 고른다.
- **프레임 수 유지**: 32×32px, 발끝 y=29, idle 2·walk 4·run 4 프레임과 파일 이름·레이어 순서(`docs/specs/sprite-spec.md`)를 그대로 둔다. 기준점이 바뀌면 sprite-spec 과 `PetKind` 기준점을 함께 고친다.
- **배지 그림**: 배지마다 24×24 도트 그림 하나. 못 받은 배지는 같은 그림을 회색·흐리게 보인다.
- **앱 아이콘·스플래시**: 새 앱 패키지 없이 도구 스크립트로 PNG·리소스를 만든다.
- **글꼴 서브셋**: fonttools 로 앱 문구에 쓰는 글자만 남긴다. fonttools 는 개발 도구이고 앱 의존성이 아니다.

## 결과

- 그림을 바꿔도 앱 코드·에셋 경로는 그대로이고, 기존 스프라이트 테스트로 레이어 어긋남을 잡는다.
- 추가 비용이 없고, Mac·Windows PC 어디서나 같은 명령(`fvm dart run tool/render_sprites.dart`)으로 다시 만든다.
- 손으로 그리는 편집기보다 그리는 속도가 느리고, 그림 품질은 미리보기 PNG 를 보며 고치는 반복에 달려 있다.
- 후보 결과물은 투표가 끝나고 작업 18 에서 지운다.
