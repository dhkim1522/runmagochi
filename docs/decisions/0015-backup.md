# 0015 백업은 JSON 파일 하나로 내보내고, 가져오면 전체를 바꾼다

- 상태: 채택
- 날짜: 2026-10-18

## 배경

- 로컬 우선 앱이라 폰을 바꾸거나 앱을 지우면 기록이 사라진다 (결정 0001). 서버 없이 쓸 수 있는 복구 수단이 필요하다.
- 기기 간 합치기는 같은 러닝이 양쪽에 있을 때 충돌 규칙이 필요해 복잡하다.

## 결정

- 파일은 JSON 하나다: `{format: "runmagochi-backup", version: 1, schemaVersion: 3, exportedAt, tables: {...}}`.
  - `version` 은 파일 형식 번호, `schemaVersion` 은 만든 시점의 DB 스키마 번호다. 지금은 `schemaVersion` 3 만 읽는다. 스키마가 바뀌면 이전 번호를 새 번호로 바꾸는 변환을 더한다.
  - 행은 drift 의 JSON 모양이다. 시각은 ISO-8601 문자열이다.
- 담는 테이블: Runs(완료된 것), Splits, Avatars, WeeklyGoals, XpTxns, Profiles. 삭제 표시된 행도 담는다.
- 담지 않는 것: RunPoints(용량이 크고, 거리·구간·경로는 Runs·Splits 에 요약돼 있다), 진행 중 러닝과 거기에 딸린 Splits·XpTxns.
- 가져오기는 **전체 바꾸기**다. 파일을 먼저 검증하고, 통과하면 한 트랜잭션에서 기존 모든 테이블(RunPoints·진행 중 러닝 포함)을 지운 뒤 파일 내용을 넣는다. 검증이나 삽입이 실패하면 기존 데이터가 그대로다. 합치기는 하지 않는다.
- 진행 중인 러닝이 있으면 가져오기를 막는다(화면은 작업 13).
- 파일 저장·열기는 `file_picker`(Android·iOS 지원, 결정 0014)를 쓴다(작업 13).
- 읽을 수 없는 파일은 `BackupFormatException` 의 한국어 메시지로 알린다.

## 결과

- 새 기기에서 완료된 러닝·성장·목표·체중을 되살릴 수 있다. 가져오기 전에 있던 데이터는 사라진다는 확인 문구가 필요하다.
- 가져온 뒤 RunPoint 가 없어 러닝 끝부분 잘라내기는 옛 러닝에 쓸 수 없다.
- 스키마를 바꿀 때마다 백업 변환을 함께 만들어야 한다.
